## Modular Architecture — The Rational Take

**The temptation:** build a fancy shared SDK + UI library + plugin framework on day 1.
**The trap:** premature abstraction. You don't know the right shape until app #2 actually exists.

**The rule:** Build app #1 as a single Next.js app with clean module boundaries. When app #2 starts and needs the *same* code, **then** extract it into a `packages/` directory. Not before. Duplication is cheaper than the wrong abstraction.

### Day-1 Setup (cheap things to do now)

| Decision | Choice | Why |
|---|---|---|
| Repo strategy | **Monorepo** with `pnpm` workspaces | Zero migration friction when app #2 arrives. |
| Build orchestrator | **Turborepo** | Caches builds, parallel tasks, free. |
| Folder layout | `apps/*` for products, `packages/*` for shared (initially empty) | Industry-standard, no surprises. |
| App framework | **Next.js 15 (App Router)** for each app's dashboard + webhook handlers | Vercel/Railway deploys cleanly. |
| Database | **Neon Postgres** (one project, schema-per-app, branching for preview envs) | Branching lets us spin up a copy of prod per PR — killer for testing webhook handlers. Serverless scaling matches spiky cron + webhook bursts. |
| ORM | **Drizzle** (migrations via `drizzle-kit`) | Lighter than Prisma; faster cold starts (matters for webhook latency); SQL-fluent for review/loyalty aggregation queries; edge-runtime compatible. |
| Hosting | **Vercel** for app dashboards + **Railway/Fly** for workers | Solo-dev friendly. |
| Media storage | **Cloudflare R2** | S3-compatible, zero egress fees — critical for video reviews. |
| Email | **Resend** (transactional + marketing/broadcasts) | Unified email sender for all review emails. |
| SMS | **Twilio** | Industry standard. |
| Observability | **Sentry** + **Posthog** + **BetterStack** | One account, all apps. |
| Auth (for Wix install) | Wix's OAuth — bare implementation in each app initially | Cheap to copy once; abstract on app #2. |

### Day-1 Folder Layout

```
wix-apps/
├── apps/
│   └── reviews/                       # App #1: Visual UGC Reviews
│       ├── app/                       # Next.js App Router
│       ├── lib/
│       │   ├── wix/                   # Wix SDK wrapper — extraction candidate
│       │   ├── billing/               # App Market billing — extraction candidate
│       │   ├── auth/                  # OAuth install flow — extraction candidate
│       │   ├── media/                 # R2 upload helpers — extraction candidate
│       │   ├── email/                 # Resend wrapper — extraction candidate
│       │   ├── sms/                   # Twilio wrapper — extraction candidate
│       │   └── db.ts                  # Drizzle client (Neon serverless driver)
│       └── drizzle/
│           ├── schema.ts              # Tables, enums, relations
│           └── migrations/            # generated by drizzle-kit
├── packages/                          # Empty until app #2 forces extraction
├── turbo.json
├── pnpm-workspace.yaml
└── package.json
```

### Extraction Trigger Rule

Extract a folder from `apps/reviews/lib/X/` into `packages/X/` **when and only when** app #2 needs to copy-paste it. At that point:
1. Move the folder to `packages/X/` (e.g. `packages/wix-sdk/`).
2. Replace duplicated code in app #1 with the package import.
3. Add a single set of unit tests at the package level.
4. Lock the package to a workspace version in both apps' `package.json`.

Apply this exactly once per shared concern. Don't pre-extract.

### Likely Extraction Order (predicted)

By the time app #2 (Loyalty) ships, expect to extract — in this order:
1. `@wix-apps/wix-sdk` — OAuth, REST/SDK client, webhook signature verification, rate limit + retry.
2. `@wix-apps/billing` — Wix App Market plan upgrade/downgrade webhooks, plan-state lookups.
3. `@wix-apps/email` and `@wix-apps/sms` — Resend + Twilio wrappers with templating.
4. `@wix-apps/ui` — design tokens (Tailwind config) and a couple of admin-dashboard primitives (Card, StatsBlock, EmptyState).
5. `@wix-apps/db` — base `Account`, `Site`, `Subscription` Drizzle schemas (plus the Neon client wrapper) that every app re-uses.

By app #3 (Subscriptions), the marginal cost of launching a new app collapses to ~50% of app #1's build time. That's the payoff.

### What NOT to share

- **UI dashboards** — each app's settings screens are too different. Share design tokens, not screens.
- **Domain logic** — review moderation logic ≠ loyalty rules ≠ subscription dunning. Keep specific to the app.
- **Database tables** — each app has its own schema. Only the shell models (Account, Site, Subscription, AuditLog) are shared.

## Risks to Watch

- **Wix ships native parity** for any one feature → mitigated by speed and depth (we go deeper than Wix will).
- **Distribution is in-app only** → free tier must rank in App Market category; content marketing is leverage.
- **Wix merchant ARPU is lower than Shopify** → outcome-based pricing where possible (per review collected, per booking filled, per resolved chat).
- **Solo-team bus factor** → write everything down. This file is the entry point.
